# v0.6 M0: connector matrix and LLM call-site audit

This v0.6 inventory freezes the three reference projects at OmniRoute [`d1ba82234c260e2cf6b0f3ac307a75240d5bbdc5`](https://github.com/diegosouzapw/OmniRoute/tree/d1ba82234c260e2cf6b0f3ac307a75240d5bbdc5) (2026-10-27), CLIProxyAPI [`ad8bdd3f20bef44f0684b8a6096a216b2c76040d`](https://github.com/router-for-me/CLIProxyAPI/tree/ad8bdd3f20bef44f0684b8a6096a216b2c76040d) (2026-10-27), and Sub2API [`f178e5ae32659e8901644a9f2378a0439ffa36ae`](https://github.com/Wei-Shaw/sub2api/tree/f178e5ae32659e8901644a9f2378a0439ffa36ae) (2026-10-27). It inventories every in-scope conversational account/auth mode and upstream API family selected from those revisions and maps it to Stroom execution work below. Inclusion means the connector is required in the v0.6 execution plan; it does not claim a credential, entitlement, model, or live request was validated. This source review used no provider credentials and made no upstream requests.

## Frozen three-project account/API union and Stroom execution mapping

This is the complete in-scope union, normalized by **service + account/auth mode + upstream API family**. The source repositories expose many additional model aliases and endpoints; aliases are not new account connectors. Provider catalog entries are included below only when they execute conversational model turns. Browser cookies/web sessions; public Stroom API ingress; embeddings/rerank; Decision models/APIs; tenant/customer key, quota, billing, or proxy-operator workflows; non-conversational media/tool endpoints; and the Kiro third-party OAuth integration prohibited by its pinned terms are excluded. Images, audio, video, and files carried inside a chat turn remain supported content requirements. The three projects are evidence sources, not implementations Stroom may copy.

The existing Stroom path in this inventory is the current v0.6 capability boundary, not an assertion that all account entries below are already usable. Every listed in-scope mode is a required connector execution item: its account/auth state must resolve through the account registry and its model calls must run through the shared `ChatAdapter`/`ChatService` route used by Chat and Task Flow. Credentials that Stroom owns must use secure credential references; CLI-owned sessions remain separately identified account entries whose local bridge follows the source contract without importing the CLI token into Stroom. Anonymous/no-auth entries use the documented request semantics and do not prompt for credentials. Stroom's current generic provider rows or stored legacy labels do not count as an implementation of a reference login flow.

## Stroom LLM call-site audit

The source audit searched production Dart under `lib/` for `ChatAdapter`, `ChatService`, `createChatProviderFromConfig`, `sendPrompt`, stream entry points, LLM endpoint/protocol strings, and HTTP client request calls, then followed each service construction and request path. At the audited base commit, `ChatAdapter` is the shared provider-resolution boundary for chat: it creates per-conversation or transient `ChatService` instances, and `createChatProviderFromConfig` selects the OpenAI-compatible or Anthropic provider. Those providers own the chat HTTP clients. `OcrService` separately sends image content to an OpenAI-compatible Chat Completions endpoint; despite being an OCR feature, that is a direct model request and is inventoried below.

### Explicit exclusions

OCR, ASR, TTS, MCP transport, HTTP tools, web search tools, file upload/download APIs, connectivity probes for MCP/HTTP tools, and other non-LLM service requests are outside this LLM router unless they make an LLM request. `OcrService` is the OCR exception here: it sends a multimodal Chat Completions request and is in scope, as listed above; OCR image preparation and local processing are not separate model calls. ASR and TTS endpoints remain outside this chat-account router. In particular, a tool call initiated by an assistant has an in-scope LLM decision request and a separate out-of-scope tool/service request. `ModelConfigPage`'s direct audio test is TTS, not an LLM test. No other direct production LLM endpoint call was found beyond `OcrService` and the chat provider boundary.
