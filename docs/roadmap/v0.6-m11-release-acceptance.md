## Migration, backup, and media evidence

The source audit covered the resumable `ConversationMigrationService`, stable-ID record adapter, native SQLite and Web IndexedDB conversation repositories, attachment/media storage, backup file inventory, archive validation, and selective restore. Existing tests exercise migration interruption/verification, schema-version fallback, account migration/backups, archive inventory, missing files, selection behavior, and attachment round trips. Focused command results for this M11 candidate are recorded below.

Manual media check: export a backup with **Chat records and attachments** and the required media/task categories selected; confirm the archive contains the corresponding `attachments/`, `task_flow_attachments/`, `pictures/`, `tts_audio/`, `videos/`, or `texts/` entries; restore to a test profile/device and open a message or task referencing a file. A metadata-only reference does not prove the bytes are present. Always export the current device before selected-category restore.

Platform behavior: Android export uses the selected public location through the Storage Access Framework; iOS export uses the app Documents backup location; desktop manual export opens a Save dialog initialized to Documents and writes to the user-selected location. The configured desktop backup root defaults to Documents/Stroom/AutoBackups where available. Web does not provide the native automatic backup location and uses file-based manual import/export. These paths are code-reviewed and have fixture coverage, but local tests do not certify physical-device permissions, browser-origin migration, keystore recovery, or platform app-store builds.

M0a's approved fixed-revision audit identifies OmniRoute (`d1ba82234c260e2cf6b0f3ac307a75240d5bbdc5`, MIT), CLIProxyAPI (`ad8bdd3f20bef44f0684b8a6096a216b2c76040d`, MIT), and Sub2API (`f178e5ae32659e8901644a9f2378a0439ffa36ae`, LGPL-3.0) as design/API references. The final v0.6 source, tracked assets, dependency declarations, and the existing About → Open Source Licenses registration were inspected: Stroom uses an independent implementation based on public API/protocol documentation and contains no copied source or assets from these three projects. Their license texts are not Stroom runtime dependencies and are not added as bundled third-party entries. Existing unrelated vendor/package notices remain registered through the current `LicenseRegistry`/`registerBundledAssetLicenses()` path.

The approved comparative roles are: OmniRoute for provider/account organization and route visibility; Sub2API for account/session UX; CLIProxyAPI for protocol execution boundaries and source-scoped reasoning/signature safeguards. Stroom's conversation repository remains the source of complete local history. These named projects are design references only; Stroom's code is its independent implementation.
