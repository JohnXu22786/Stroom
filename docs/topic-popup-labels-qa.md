# Topic popup label QA

The captures compare the same real Flutter `TopicItem` popup rendered in Chromium at a 240 × 360 CSS pixel viewport, `de-DE`, 1.5× text scale, light theme, with the menu open. `topic-popup-labels-before.png` is the unmodified baseline; the after captures were produced from the updated app. `topic-popup-labels-comparison.png` places the baseline, initial after frame, and tail endpoint side by side. The source captures remain at their full 240 × 360 resolution.

The `read_state` and `auto_rename` labels begin stationary after the existing delay, then move horizontally to reveal their complete trailing text and pause at the endpoint before reversing. `auto_rename` already used `ConstrainedText`; the measured-size fix now on `main` lets it reach the true endpoint. The `read_state` change in this PR uses that same widget. The read-state 20 px leading icon and 12 px gap retain their original geometry. `rename`, `pin`, and `delete` fit; `toggle_temporary` still wraps naturally and is unchanged. The playable `topic-popup-labels-scroll-preview.webm` shows the open-menu head, initial delay, scroll, endpoint pause, and start of reversal.

The narrow caller regression uses a 240 px viewport and a 500 px horizontally scrollable `TopicItem` fixture so the popup remains constrained by the narrow viewport while unrelated topic-card subtitle/date layout has enough width. During diagnosis, a 360 px `TopicItem` fixture at 1.5× produced a pre-menu `RenderFlex` overflow in the existing subtitle/date `Row` at `topic_item.dart:165` (max width 180 px; 112 px overflow). This layout is outside the popup change and was not modified.
